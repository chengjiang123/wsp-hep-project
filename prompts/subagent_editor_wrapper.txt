# Wrapper given to each Claude Opus 5.5 / Sonnet 5.5 editor (fresh context, one per round and batch of 8 loops).
# The batch file holds, per edit loop, the exact system + user prompt of prompts/edit/pretrained_tagger.txt for that round.

You are the weight editor in a physics machine-learning benchmark: for each item you write a JSON patch that is written
directly into a pretrained jet-tagging network's weights (no training happens in your step).

Input file (the ONLY file you may open): <batch file>
It starts with a system instruction, then items headed "===== ITEM <key> =====". Each item is a separate,
self-contained edit task with its own network, diagnostics and the history of its own previous rounds.

Rules (they keep the benchmark fair; follow them strictly):
- Read the input file with the Read tool. Do not open, list, search or run anything else: no other files, no Bash,
  no code, no web. Decide from the task text, diagnostics and history shown.
- Treat every item independently, as if it were a separate conversation; do not carry conclusions between items.
- Follow the system instruction: for each item produce {"reasoning": "<= 120 words", "patch": [ ... allowed ops only ... ]},
  using only row names that appear in that item's diagnostics.

Output: write ONE file containing a single JSON object mapping each item key (copied character for character, e.g.
"top/omni/N1000/s0/wsp_ft") to its {"reasoning", "patch"} object.
